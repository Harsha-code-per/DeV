DeV Code docs

DeV Code is a coding agent for your terminal. Start it with devcode in your project folder.

Install

On Linux or macOS:

curl -fsSL https://trydev.work/install | sh

On Windows, in PowerShell:

irm https://trydev.work/install.ps1 | iex

With npm:

npm i -g @devcodeagent/cli

With pnpm:

pnpm add -g @devcodeagent/cli

With bun:

bun add -g @devcodeagent/cli

On Debian, Ubuntu, Mint and Pop!_OS:

curl -fsSLo /tmp/devcode.deb https://github.com/Harsha-code-per/DeV/releases/latest/download/devcode-linux-x64.deb && sudo apt install /tmp/devcode.deb

On Fedora, RHEL, Rocky and AlmaLinux:

sudo dnf install https://github.com/Harsha-code-per/DeV/releases/latest/download/devcode-linux-x64.rpm

On ARM Linux, use devcode-linux-arm64.deb or devcode-linux-arm64.rpm instead. With Scoop on Windows:

scoop install https://github.com/Harsha-code-per/DeV/releases/latest/download/devcode.json

The install scripts and the npm package check every download against the release's SHA-256 checksums before installing anything, and every release lists the checksums of its packages. To update, run devcode upgrade. If you installed with a package manager, it tells you the command to run.

Use DeV in VS Code

The DeV Code extension opens DeV in a terminal beside your file and tells it what you're looking at. Install DeV first, then the extension:

curl -fsSLo /tmp/devcode-vscode.vsix https://github.com/Harsha-code-per/DeV/releases/latest/download/devcode-vscode.vsix && code --install-extension /tmp/devcode-vscode.vsix

Press Ctrl+Esc (Cmd+Esc on macOS), or the DeV button above the editor, to open DeV. Your selection goes to DeV as you move, shown beside its prompt, so you can ask about "the selected function" without copying it. Ctrl+Alt+K (Cmd+Alt+K) mentions the selected lines in what you're writing. The extension talks to DeV over a local connection that only the terminal it opened can use.

Connect a model

Start devcode in a project folder and type /connect. Pick a provider, paste its key, and you're ready. DeV saves the key in its own private store, so you don't need env variables or a .env file.

If a provider's key is already in your shell, /connect offers to use it. It's never picked up silently.

Scripts and CI have nobody to answer that question, so devcode run does read keys from the environment.

Free models

DeV Code costs nothing, and you can run it on free models. The list in /connect puts providers with a free tier first, with the best starting point at the top. Local models on your machine are found automatically.

The default model is auto/free. For each request it tries the free models you've connected, moves to the next when one is busy, and remembers which ones answer well for you. It never uses a paid model unless you choose one.

Each provider sets its own free limits and terms. When every model is rate limited, DeV waits if the limit clears soon and tells you what it's doing. If it can't, it ends with a clear error. Connecting a second provider gives you more room.

Some free tiers allow only a small amount per minute. DeV sends those a smaller request, so they suit short tasks. /connect marks them.

Modes

DeV chooses how to work and shows you in the prompt. Press Shift+Tab to cycle the modes yourself, or start in one with --permission-mode.

ModeWhat happens
ManualDeV asks before it edits files or does anything risky. Commands in its sandbox run without asking.
Accept editsFile edits go ahead; everything else asks as usual.
PlanFor larger or unclear work. DeV reads the code and writes a plan, and changes nothing until you approve it.
AutoDeV never asks. Risky actions (deleting folders, force pushes, publishing, sudo, leaving the sandbox, writing outside the project, secrets files) are refused and DeV finds another way; after three refusals in a row, or twenty in a session, it asks you. To let one through, allow it in /permissions.
GoalAuto, and DeV keeps working on your next message until it is true, such as "the tests pass", and a separate reviewer confirms it. Also /goal <objective>; control it with /goal pause, /goal resume and /goal clear. In scripts: devcode run --auto "/goal <objective>". An unfinished goal comes back when you continue the session.

DeV decides from how you word the request, so unusual wording may just start in Manual. You can switch at any time, or say "without planning" to skip a plan. Plan approval still asks you in Auto, because it is your decision and not a permission.

To run one prompt from a script:

devcode run "explain this repo"

To get the result as JSON:

devcode -p "fix the failing test" --output-format json

To work in a git worktree of its own, on branch devcode/fix-login, so parallel sessions don't collide:

devcode -w fix-login

When you exit, a worktree with no changes is removed. One with changes is kept; run the same command to continue in it.

Configuration

Settings live in dev.json, either in your project or in ~/.config/dev/. Project memory lives in DEV.md. DeV also reads AGENTS.md.

{
  "sandbox": {
    "network": { "allow": ["npm.mycompany.com"] },
    "filesystem": { "allowWrite": ["~/shared"], "allowRead": ["~/.npmrc"] }
  },
  "hooks": {}
}

Hooks: PreToolUse, PostToolUse, UserPromptSubmit, Stop and SessionStart run as shell commands that get JSON on stdin. Exit code 2 blocks the action.

Security

DeV treats the model as untrusted, because text it reads can try to steer it.

  • On Linux and macOS, shell commands run in an OS sandbox. They can write only to your project, temp folders and package caches.
  • They can't read ~/.ssh, ~/.aws, other credential stores or DeV's key store.
  • Network access goes through an allowlist of package registries and git hosts.
  • Leaving the sandbox always asks you, unless you turned on Auto.
  • File edits and web fetches ask by default. Deny rules win in every mode.
  • Web pages and MCP results reach the model marked as untrusted.
  • Web search goes to Exa or Parallel, free services that need no key, and only the search words are sent. A page that only shows its content after JavaScript runs is read through Jina Reader, which receives just the page address. Deny websearch or webfetch in your settings to turn either off.

Limits: Windows has no sandbox yet, PowerShell commands are never sandboxed, and local MCP servers run outside the sandbox. Read the full security policy.

Benchmarks

DeV Code passes 27 of 30 benchmark tasks on free models, at no cost, with one run of each task. The tasks use hidden tests, and a do-nothing agent fails all of them. The tasks and results are in the bench folder.

FAQ

Is it really free?

Yes. DeV Code is free and open source, with every feature included. Model providers set their own limits on their free tiers.

Can I use it for commercial work?

Yes. DeV Code is MIT licensed. Check the terms of the model provider you connect, especially for free tiers and sensitive code.

Can I use my own paid model?

Yes. Connect any provider with /connect and pick a model with /models.

Does it send my code anywhere?

Only to the model provider you connect, or nowhere if you use a local model.

Why did a long task stop on a free model?

Some free tiers limit how much you can send per minute. Connect another provider with /connect.
