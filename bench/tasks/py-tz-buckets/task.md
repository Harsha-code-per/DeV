`daily_totals` in `usage.py` builds the per-day usage report customers see on their invoice, and they report it is wrong: usage near midnight lands on the wrong day for part of the year, and the report always leaves out the last day.

Fix it. Each event is `(timestamp, amount)`, where `timestamp` is an ISO 8601 string with a UTC offset (`Z` or `+hh:mm` / `-hh:mm`, not necessarily UTC) and `amount` is an integer. An event belongs to the calendar day it falls on in the time zone `tz` (an IANA name such as `Europe/Berlin`) at the moment it happened, so daylight-saving changes must be respected. The result is a dict `{"YYYY-MM-DD": total}` with an entry for every day from the first event's day to the last event's day inclusive (days without events are 0), in date order. No events gives `{}`. The result must not depend on today's date.
